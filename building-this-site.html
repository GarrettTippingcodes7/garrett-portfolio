Experiment · No. 1

Building this site

Directing AI to build my portfolio’s components inside a design system I defined first.

This site is the experiment. I designed the brand system first, then connected a Claude agent to my Figma files and directed it to build components matching that style using the content I provided. I placed them in Figma Sites like building blocks and fixed bugs and made changes from there. Then I rebuilt the whole site in code with Claude Code.

Role
Solo Designer
Tools
Figma, Figma Sites, Claude, Claude Code, Netlify
Timeline
Jun – Nov 2026

The experiment

I built the first version of this site by hand in Figma Sites, with a Claude agent working with me. This was my first time working with an agent and I wanted to see where this would fit into my process and how good Claude did at matching my existing design style, and where my own judgment had to step in.

Currently Claude is not able to access Figma Sites files, so I built all of my components in regular design file and uploaded them to my asset library as a work around.

The rules came first

Rule

One brand system

Navy, cream, and teal. Big Shoulders Display for titles, Epilogue for body. One card style and one hover state. Every component had to match.

Rule

Four breakpoints

Desktop XL, Desktop, Tablet, and Mobile on every page. A component wasn’t done until it held up at all four.

Rule

The page sets the spacing

No outer padding on components unless they’re cards. The page frame controls spacing, so every block drops in clean.

How the work split

Phase one was hand-building. I laid out every page myself and brought Claude in to debug: choppy accordions, an orphaned card stretching full width, and a sticky nav that turned transparent.

Phase two started when Claude could edit my files. It built the Evidence Ledger, About page concepts, a wireframe kit, and case study sections. I reviewed, rejected, and combined. Then I assembled everything in Sites and fixed what broke there.

Where my judgment came in

Directing AI well came down to catching what it got wrong. These three moments shaped how I work with it.

Problem:

It said it was fixed. It wasn’t.

The About page header images kept breaking on tablet and mobile. Claude reported a fix several times, and each one failed. It had only tested at the exact breakpoint widths.

Solution:

Make it prove the fix

I rejected each attempt until we found the real causes: a disconnected component copy, a locked aspect ratio that collapsed in Sites, and instance overrides. A fix isn’t done until it holds at in-between widths too.

Problem:

Changes I didn’t ask for

While linking 28 components to my library colors, Claude silently reset their opacity to 100%. Subtle teal accents turned solid, and white text ended up on full teal.

Solution:

Review every change

I caught it on review, and we fixed 34 affected chips. A confident summary isn’t proof, so every batch of AI edits gets a visual check before I accept it.

Problem:

One answer is a guess

Asking for a single About page design would have given me Claude’s taste, not mine.

Solution:

Ask for options, then choose

I had it draft three directions: a standard layout, a bento grid, and a field work order. I kept Option A’s structure because it’s easy for a recruiter to scan, then pulled the profile fields from C so my field background sits right in the header. Nothing from B made the cut. Same with the Evidence Ledger, where I picked Option 3, and the hover timing, where I reverted its change back to 250ms.

Where I still had to do it myself

Some problems AI couldn’t see. A hover flicker looked like a font bug, and Claude chased several wrong theories. I solved it by remembering I’d removed some auto layout nesting and missed a few hover variants.

Figma Sites had quirks no component could fix: instances keeping fixed widths, fixed navs that must be top-level layers, and “deleted” layers that were only hidden on smaller breakpoints. Setting every instance to Fill on every breakpoint became a routine step.

Part two: rebuilding it in code

Figma Sites got me live, but it limited what I could fix. So I handed my published site to Claude Code and had it rebuild every page as plain HTML, CSS and JavaScript, hosted on Netlify. Same direction-and-review loop, with a new medium.

I set the brief: one consistent header and footer, my LinkedIn recommendation, real contact details, a working contact form, and the brand details like the teal cursor and highlight. The judgment calls were still mine. I caught a case study section rebuilt in the wrong order, images sitting in boxes that didn’t match the page, and text that wasn’t filling its space, and I decided which images should stay still.

The result

Seven pages, three case studies, and an art and experiments page. Version one was built at four breakpoints and published straight from Figma. Version two is plain code I own and can change freely: images about 60% lighter, one shared header and footer, and a 404 page that works like a terminal.

What I’d do differently

Link the library from day one. I built components before connecting my color and type styles, then had to retrofit them. Starting with the library would have kept everything consistent from the start.

Capture as I go. I didn’t save before-and-after shots, so this case study was rebuilt from chat history and Figma version history. Now I screenshot before accepting a change and save named versions at milestones.

AI is fast at building blocks. Deciding what the blocks should be, and noticing when they’re wrong, is still the job.
